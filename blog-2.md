# `Pick` and `Omit`: Keeping Your TypeScript Code DRY with Utility Types

## Introduction

In large TypeScript projects, one of the most common traps developers fall into is **interface duplication** — copying the same interface over and over with slight modifications. Imagine you have a master `User` interface, and across your application you need a `UserPreview` (just name and email), a `UserWithoutPassword` (everything except the password), and a `CreateUserDTO` (no auto-generated fields). Writing each of these by hand violates the **DRY (Don't Repeat Yourself)** principle and creates a maintenance nightmare.

TypeScript's built-in **`Pick`** and **`Omit`** utility types solve this problem elegantly. Instead of duplicating interfaces, you derive specialized "slices" from a single master type. In this blog, we will explore how these two tools work and why they are essential for writing clean, maintainable TypeScript.

---

## The Problem: Interface Duplication

Let us first see what duplication looks like in practice:

```typescript
// Master interface
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  age: number;
  role: "admin" | "user";
}

// Bad approach — manually copying fields
interface UserPreview {
  id: number;
  name: string;
  email: string;
}

interface UserProfile {
  id: number;
  name: string;
  email: string;
  age: number;
  role: "admin" | "user";
}
```

The problem here is clear: if a field in `User` is renamed, its type changes, or a new required field is added, you must hunt down and update every duplicated interface manually. This process is error-prone and does not scale.

---

## `Pick`: Select Only What You Need

`Pick<T, K>` creates a new type by selecting only the specified keys `K` from a master type `T`. Everything else is excluded.

### Syntax

```typescript
Pick<OriginalType, "key1" | "key2">
```

### Basic Example

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  age: number;
  role: "admin" | "user";
}

// Select only the fields you need
type UserPreview = Pick<User, "id" | "name" | "email">;

// Equivalent to:
// type UserPreview = {
//   id: number;
//   name: string;
//   email: string;
// }

const preview: UserPreview = {
  id: 1,
  name: "Alice",
  email: "alice@example.com",
};
```

### Real-World Use Case: Shaping a Public API Response

```typescript
interface Product {
  id: number;
  name: string;
  description: string;
  price: number;
  stock: number;
  supplierId: number;
  internalCode: string; // Internal use only — clients should never see this
}

// Expose only safe, public fields via the API
type PublicProduct = Pick<Product, "id" | "name" | "description" | "price">;

function getPublicProduct(product: Product): PublicProduct {
  return {
    id: product.id,
    name: product.name,
    description: product.description,
    price: product.price,
  };
}
```

By using `Pick`, if `Product` ever gains a new internal field, `PublicProduct` will never accidentally expose it — you have to explicitly choose what gets included.

## `Omit`: Remove What You Do Not Need

`Omit<T, K>` is the inverse of `Pick`. Instead of selecting specific keys, it **removes** the specified keys from the master type and keeps everything else.

### Syntax

```typescript
Omit<OriginalType, "key1" | "key2">
```

### Basic Example

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  age: number;
  role: "admin" | "user";
}

// Keep everything except the password
type UserWithoutPassword = Omit<User, "password">;

// Equivalent to:
// type UserWithoutPassword = {
//   id: number;
//   name: string;
//   email: string;
//   age: number;
//   role: "admin" | "user";
// }

// Omit multiple fields at once
type UserPublicProfile = Omit<User, "password" | "role">;
```

### Real-World Use Case: DTO Pattern for Creating and Updating Records

A very common pattern in backend development is using **Data Transfer Objects (DTOs)** — types that define exactly what data a client must send. `Omit` is perfect for this:

```typescript
interface BlogPost {
  id: number;
  title: string;
  content: string;
  authorId: number;
  createdAt: Date;
  updatedAt: Date;
}

// When creating a post, the client does not send id, createdAt, or updatedAt
// — these are generated by the server
type CreateBlogPostDTO = Omit<BlogPost, "id" | "createdAt" | "updatedAt">;

// When updating a post, id is required, but all other fields are optional
type UpdateBlogPostDTO = Partial<Omit<BlogPost, "id">>;

function createPost(data: CreateBlogPostDTO): BlogPost {
  return {
    ...data,
    id: Math.floor(Math.random() * 10000),
    createdAt: new Date(),
    updatedAt: new Date(),
  };
}

function updatePost(id: number, changes: UpdateBlogPostDTO): void {
  console.log(`Updating post ${id} with`, changes);
}
```

## `Pick` vs `Omit`: Choosing the Right Tool

| Situation | Use |
|---|---|
| You need only 2–3 fields from a large interface | `Pick` |
| You need most fields, excluding just 1–2 | `Omit` |
| Hiding sensitive data like passwords or tokens | `Omit` |
| Defining a specific API request or response shape | `Pick` |
| Removing auto-generated server fields from a DTO | `Omit` |

A useful rule of thumb: if you are **including** a small number of fields, use `Pick`. If you are **excluding** a small number of fields, use `Omit`.

## Combining with Other Utility Types

`Pick` and `Omit` become even more powerful when combined with other TypeScript utility types:

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  password: string;
  age: number;
}

// All update fields are optional (for PATCH requests)
type PartialUserUpdate = Partial<Pick<User, "name" | "email" | "age">>;

// A read-only display version — cannot be mutated
type ReadonlyUserDisplay = Readonly<Omit<User, "password">>;

const update: PartialUserUpdate = {
  name: "Bob", // email and age are optional
};

const display: ReadonlyUserDisplay = {
  id: 1,
  name: "Bob",
  email: "bob@example.com",
  age: 30,
};

// display.name = "Alice"; // Error: Cannot assign to 'name' because it is a read-only property
```

## Conclusion

`Pick` and `Omit` are two of TypeScript's most practical utility types. They allow you to maintain a **single source of truth** for your data shapes and derive all the specialized variants you need from it — without copying a single line.

The benefits are clear:
- **DRY code** — change your master interface once and all derived types update automatically
- **Type safety** — no risk of forgetting a field or mismatching a type during manual copying
- **Readable intent** — a developer reading `Omit<User, "password">` immediately understands the purpose without needing any comments

> **"Don't copy your interfaces. Derive them."**
> A well-designed master interface combined with `Pick` and `Omit` will make your entire codebase cleaner, safer, and far easier to maintain.
